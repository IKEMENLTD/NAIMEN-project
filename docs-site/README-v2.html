Trinity System v2

Mission: イケメンの構造化

外面、内面、経済面が上位20%（80点以上）で初めて真のイケメンと定義。本プロジェクトは第一フェーズ、内面のスコアリングシステムを実装します。

Trinity - 三位一体

内面は3つの力で構成されます：

認識力 (Perception)

何が見えているか - 現実をありのまま見る力

判断力 (Judgment)

何が重要か - 本質を掴み、優先順位をつける力

実行力 (Execution)

何をするか - 選択を現実にする力

スコア計算式

total_score = min(perception, judgment, execution) × growth_coefficient

Trinity の哲学: 3つの力のうち、最も低い力がボトルネックになります。

アーキテクチャ

2シート構成

従来の7シートから2シートへ最適化しました。

  • users - ユーザーの現在の状態を保持
  • events - 全イベント履歴（イベントソーシング）

イベントタイプ

  • obs - observation（観察記録）
  • jdg - judgment（判断記録）
  • exec - execution（実行記録）
  • score - score_update（スコア更新）
  • growth - growth_calc（成長係数計算）

3体のエージェント

The Observer（観察者）

  • 役割: 認識力を評価
  • 頻度: 毎日朝6時
  • 評価対象: 日記分析、認知バイアス検出

The Judge（審判者）

  • 役割: 判断力を評価
  • 頻度: 毎週日曜21時
  • 評価対象: 論理性、優先順位の一貫性

The Executor（執行者）

  • 役割: 実行力を評価
  • 頻度: 毎日夜22時
  • 評価対象: 完遂率、即行動性、継続力

クイックスタート

1. スプレッドシート作成

users.csv と events.csv をGoogleスプレッドシートにインポート

2. GAS APIデプロイ

Code.gs を Apps Script にコピー
SPREADSHEET_ID を設定
Web Appとしてデプロイ

3. エージェント実行

cd agents-v2
cp .env.example .env
# .env を編集（TRINITY_API_URL を設定）

npm run observer
npm run judge
npm run executor

詳細なデプロイ手順は DEPLOYMENT-v2.md を参照してください。

v2の改善点

  1. シンプル: 7シート → 2シート（71%削減）
  2. 統一API: 7エンドポイント → 3エンドポイント（57%削減）
  3. 拡張性: 新しいイベントタイプを追加するだけで機能拡張可能
  4. デバッグ容易: 全履歴がeventsシートに集約
  5. 高速: usersシートは1行のみ、eventsはappend-only
  6. スケーラブル: 外面・経済面も同じ構造で追加可能

目標スコア

イケメン基準として、各次元で80点以上を目指します：

  • 認識力 ≥ 80点
  • 判断力 ≥ 80点
  • 実行力 ≥ 80点
総合スコア = min(80, 80, 80) × 1.0 = 80点

技術スタック

  • バックエンド: Google Apps Script, Google Sheets
  • データモデル: イベントソーシング, CQRS
  • エージェント: Node.js 18+, JavaScript ES6+
