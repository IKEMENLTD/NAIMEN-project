# REVIEW-PROTOCOL.md - 多段階レビュープロトコル

## 基本方針
**品質 > スピード**。上位20%のシステムを作るため、妥協しない。

## レビュー段階

### 第1段階: 初期レビュー
- **目的**: 致命的な問題の検出
- **観点**: 科学的根拠、実装可能性、リスク
- **判定**: 
  - 🔴 致命的問題あり → 即座に修正タスク発行
  - 🟡 重大な問題あり → 改善推奨
  - 🟢 問題なし → 第2段階へ

### 第2段階: 深層レビュー
- **目的**: 本質的な改善点の発見
- **観点**: 
  - 文化的妥当性
  - 倫理的配慮
  - ユーザー体験
  - 長期的保守性
- **判定**:
  - 🔴 本質的問題あり → 再設計
  - 🟡 改善余地あり → 第3段階へ
  - 🟢 優秀 → 承認

### 第3段階: 最終検証（オプション）
- **目的**: 完璧性の追求
- **観点**:
  - エッジケース
  - パフォーマンス
  - セキュリティ詳細
  - ドキュメント完全性
- **判定**:
  - 🟢 承認 → 実装開始
  - 🟡 微調整 → 修正後承認

## レビュアーの心得

1. **妥協しない**: 「まあいいか」は禁止
2. **具体的に**: 「よくない」ではなく「なぜ」「どう直すか」
3. **本質を問う**: 「これで上位20%が作れるか？」を常に問う
4. **建設的に**: 批判だけでなく解決策を提示
5. **深く考える**: 表面的な問題だけでなく、構造的な問題を見抜く

## レビュー基準

### 科学性（30点）
- [ ] 科学的根拠が明確か
- [ ] 文化的妥当性があるか
- [ ] 測定の信頼性・妥当性が担保されるか

### 実装性（25点）
- [ ] 技術的に実現可能か
- [ ] パフォーマンスは十分か
- [ ] 保守性が高いか

### 倫理性（20点）
- [ ] プライバシーは保護されるか
- [ ] バイアスへの配慮があるか
- [ ] 透明性が担保されるか

### ユーザー体験（15点）
- [ ] 直感的か
- [ ] 負担が少ないか
- [ ] 価値が伝わるか

### 完全性（10点）
- [ ] ドキュメントが充実しているか
- [ ] エッジケースが考慮されているか
- [ ] テスト戦略が明確か

**合計80点以上で承認、60-79点で条件付き承認、60点未満は差し戻し**

## レビューループ

```
成果物提出
    ↓
第1段階レビュー
    ↓
致命的問題あり？
    YES → 修正タスク → 再提出
    NO  ↓
第2段階レビュー
    ↓
本質的問題あり？
    YES → 再設計 → 再提出
    NO  ↓
第3段階レビュー（必要時）
    ↓
承認 → 次フェーズへ
```

## レビューの記録

すべてのレビューは `ikemen-project/reviews/` に記録：
- `[component]-review-round[N].md`
- 改善履歴をトレース可能に
- 学習のためのナレッジベースとして蓄積
